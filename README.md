# NeuroStreamStudio

Приложение для прямой трансляции на стриминговые платформы (TikTok LIVE
и любые другие, принимающие RTMP) — захват экрана с наложенной веб-камерой,
кодирование и отправка потока напрямую, без необходимости в OBS.

Часть серии приложений **NEURO** для сообщества **CLUB WARZONE**.

## Что это и чего пока нет

Это **не** попытка переписать OBS Studio целиком — такая задача нереалистична
для одного приложения. Это минимальная рабочая версия: один экран + одна
камера с наложением → кодирование → RTMP на одну платформу одновременно.

**Чего пока нет** (сознательно, чтобы первая версия была рабочей, а не
бесконечной стройкой): несколько сцен с переходами, поддержка плагинов,
сложный аудио-микшер с фильтрами, захват отдельного окна вместо всего
экрана, одновременная трансляция на несколько платформ сразу, аппаратное
кодирование (NVENC/QSV) — кодирование идёт на CPU через x264, см.
"Известные ограничения" ниже.

## Как получить приложение

1. Откройте вкладку **[Releases](../../releases)**
2. Скачайте `NeuroStreamStudio.exe` **и** `ffmpeg.exe` из последнего релиза — оба файла должны лежать в одной папке
3. Запустите `NeuroStreamStudio.exe`

Сборка идёт автоматически на серверах GitHub Actions при каждом обновлении
кода — `ffmpeg.exe` скачивается и прикладывается к релизу тоже автоматически,
отдельно устанавливать FFmpeg не нужно.

## Перед первым запуском: настройте звук

Windows **не даёт доступа к системному звуку (звуку игры/десктопа) по
умолчанию** — это не ограничение NeuroStreamStudio, а особенность Windows.
Чтобы в трансляцию шёл звук игры вместе с голосом с микрофона, выберите
один из вариантов:

**Вариант 1 — Stereo Mix (если поддерживается звуковой картой)**
1. ПКМ по значку громкости в трее → Звуки → вкладка «Запись»
2. ПКМ в пустой области списка → «Показать отключённые устройства»
3. Если появился «Stereo Mix» / «Стерео микшер» — включите его правой кнопкой

**Вариант 2 — VB-Audio Virtual Cable (если Stereo Mix недоступен, например на ноутбуке)**
1. Скачайте бесплатно: [vb-audio.com/Cable](https://vb-audio.com/Cable/)
2. Установите, перезагрузите компьютер
3. В Windows установите «CABLE Input» как устройство воспроизведения по умолчанию (или настройте через «Прослушать это устройство», если нужно слышать звук самому во время стрима)

После этого в NeuroStreamStudio в списке «Системный звук» появится подходящее
устройство — приложение само подсвечивает вероятный вариант, но
финальный выбор всегда за вами.

## Как начать трансляцию

1. Получите **Server URL** и **Stream Key** вашей платформы:
   - TikTok LIVE: [livecenter.tiktok.com/producer](https://livecenter.tiktok.com/producer) (см. раздел про TikTok ниже — доступ открыт не всем аккаунтам)
   - Twitch: Панель управления трансляцией → Настройки → Поток
   - YouTube: YouTube Studio → Создать → Начать трансляцию → Потоковая передача
2. Вставьте их в соответствующие поля в NeuroStreamStudio
3. Выберите экран, камеру, микрофон и системный звук
4. Настройте позицию и размер окна камеры
5. Нажмите «Начать трансляцию»

Настройки (кроме Stream Key, который по понятным причинам стоит проверять
перед каждым стримом) сохраняются между запусками.

## Важно про TikTok LIVE

Доступ к RTMP-трансляции на TikTok — не то же самое, что на Twitch или
YouTube, где ключ доступен сразу всем:

- Обычно требуется **около 1000+ подписчиков** для разблокировки Live-доступа
- RTMP-ключ получается вручную на [livecenter.tiktok.com/producer](https://livecenter.tiktok.com/producer), **не через само приложение** — TikTok не предоставляет публичный API для автоматического получения ключа, поэтому NeuroStreamStudio не может «подключить ваш аккаунт» напрямую
- Ключ **истекает примерно через 2 часа** и выдаётся заново на каждую сессию — его нужно будет копировать перед каждым стримом, а не один раз

Это ограничение самой платформы TikTok, а не NeuroStreamStudio. Поля «Server URL»
и «Stream Key» в приложении универсальные — работают с любой RTMP-платформой,
так что можно начать тестировать на Twitch/YouTube уже сейчас, а переключиться
на TikTok, как только будет открыт доступ.

## Известные ограничения

- **Захват только всего экрана целиком**, не отдельного окна — используется DXGI Desktop Duplication, который захватывает дисплей, а не окно. Для стрима в полноэкранном режиме игры это не проблема
- **Может не работать на ноутбуках с гибридной графикой** (встроенная + дискретная видеокарта) — известное ограничение DXGI Desktop Duplication в такой конфигурации. Если захват экрана не запускается, проверьте в Параметры → Экран → Графика, какая видеокарта назначена для рендеринга рабочего стола
- **Кодирование на CPU** (x264, без NVENC/QSV) — при 1080p это ощутимо нагружает процессор. На слабом CPU стоит попробовать более низкий битрейт
- **Системный звук требует отдельной настройки** (см. выше) — Windows не даёт его по умолчанию
- **Одна платформа за раз** — трансляция сразу на несколько площадок не поддерживается в этой версии
- **Stream Key хранится зашифрованным на диске** (Windows DPAPI, привязано к вашей учётной записи Windows) — но при повторном вводе на экране показывается как обычный пароль (точки), не открытым текстом

## Структура проекта

| Файл | Назначение |
|---|---|
| `App.xaml(.cs)` | Точка входа приложения, глобальная обработка ошибок |
| `MainWindow.xaml(.cs)` | Интерфейс и оркестрация всего пайплайна |
| `ScreenCaptureEngine.cs` | Захват экрана (DXGI Desktop Duplication) |
| `CameraCaptureEngine.cs` | Захват веб-камеры (OpenCvSharp4) |
| `CompositorEngine.cs` | Наложение камеры на экран (picture-in-picture) |
| `FFmpegEncoder.cs` | Кодирование и RTMP-пуш через FFmpeg |
| `FFmpegLocator.cs` | Поиск и проверка ffmpeg.exe |
| `AudioDeviceEnumerator.cs` | Список доступных аудио-устройств |
| `StreamSettings.cs` | Сохранение настроек (Stream Key зашифрован через DPAPI) |
